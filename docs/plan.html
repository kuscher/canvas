GTK4"Not yet planning" a port
  • It is maintained. Its 28 security fixes matter for an app that opens files from anywhere.
  • It is made for pens. It has MyPaint brushes v2, pressure gain, and stylus barrel rotation (new in 3.2.6).
  • It has new tools and formats. Link and vector layers, and non-destructive filters everywhere. Among the formats are APNG, JPEG 2000, PSB export, and SVG and vector PDF export.

Termux builds GIMP 3.2.0 for Android phones. That proves GIMP 3.2 compiles and runs on Android's C library, and its recipes are where we start. Moving them up to 3.2.6 is part of the raw port.

The route

GTK3 can't draw on Android, so Canvas brings a display

GIMP is a GTK3 program. GTK4 has an Android backend, but GIMP isn't on GTK4 and has no plan to move soon. We compared four ways to get GIMP onto the screen.

How route A fits together

  • The display. termux-x11's X server became an embeddable Android library on 24 July 2026. It draws through AHardwareBuffers into a SurfaceView and resizes the X screen along with the window. It presents Android pens to GIMP as pressure, tilt and eraser devices, the same way a Wacom tablet shows up on Linux.
  • The build. Everything is compiled from source: GIMP, GEGL, babl, GTK3, Python and the file-format libraries. It uses Termux's Android recipes under Canvas's own app ID, in GitHub Actions on x86_64 runners, for both chips.
  • Googlebooks run you as Android user 10. Termux refuses to run there, because its paths assume user 0, so its ready-made packages can't be reused. Canvas builds its own folder tree inside its data folder and sets GIMP's relocation variables at launch.
  • Programs live in the native-library folder. Since Android 10, apps may not run programs from their writable storage, and GIMP starts every plug-in as its own program. So every program and library ships as lib*.so inside the APK.
  • Least privilege. There's no internet permission; GIMP's update check is compiled out, and Help opens in the browser. Shortcuts work through Android 17's CAPTURE_KEYBOARD, which is a normal permission. The X server's optional accessibility key interceptor is removed: it watches all input, and Play Protect blocks sideloaded apps that ask for it.

Why this route

  • It's the real GIMP. Every tool, filter, plug-in, script, format and shortcut, not a lookalike.
  • It runs at native speed. GIMP works on the CPU with GEGL across all cores. Nothing is emulated or virtualised.
  • The pen works from day one. Pressure, tilt and eraser reach GIMP like a Wacom does on Linux.
  • One APK covers every Googlebook. It works offline and installs like any other app.
  • Nothing gets thrown away. Every later phase builds on this base. If GIMP moves to GTK4, the build tree carries over to route C.

What it costs

  • A big build. About 150 libraries for each of 2 chips. A cold CI build takes hours; cached rebuilds take minutes.
  • A big APK. An estimated 250–350 MB for one universal APK; Krita's Android APKs are 168–179 MB per chip. If that's too big, we add per-chip APKs.
  • 3.2.0 → 3.2.6. Termux's patches stop at 3.2.0, so moving up is our work.
  • Android gaps to fill. There's no System V shared memory (a shim covers it). GTK3 only scales by whole numbers, so the 1.125× panel scales text through DPI instead. Android 17 caps app memory, so big images need GEGL tuned.
  • Nothing goes upstream. GIMP doesn't accept AI-assisted contributions, so Canvas's patches stay in Canvas.
Phases

Raw port first, then make it feel native

0

Foundations and a first window

  • Set up the repo, the ./cv helper, CI, and the signing key (outside git, backed up privately).
  • Pin termux-packages and termux-x11. A CI job builds the GTK3 stack for arm64 under Canvas's own paths and caches it per chip.
  • Build the Android shell: the window with lorie's view, the unpacker and the launcher. The X server's accessibility service, internet permission and open TCP port are stripped out.

Done when the GTK3 demo runs inside a Canvas APK on your HP, follows window resizes, and takes mouse and keyboard input.

1

The raw port → v0.1

  • The whole of GIMP 3.2.6 with GEGL and babl.
  • File formats: PNG, JPEG, TIFF, WebP, HEIF/AVIF, JPEG XL, OpenEXR, PDF, PostScript, SVG, PSD and XCF.
  • All plug-ins, including Script-Fu and Python 3.
  • Input: pen pressure, tilt and eraser; right-click; wheel and trackpad scrolling; shortcuts; text copy and paste with Android.
  • Window: fills the Canvas window and follows resizes. Text and icon sizes come from the screen density. Closing the window runs GIMP's own quit, so unsaved images still ask.
  • Both chips: arm64 tested on the HP, x86_64 on the ASUS, plus a CI smoke test.
  • Licences: notices, an About & licences page, and full sources with the release.

Done when you can do all of this on both Googlebooks: open a JPEG, PNG, PSD and XCF; paint with pressure; add a non-destructive filter; run a Script-Fu and a Python plug-in; export; quit, restart and find your settings kept.

2

At home on a Googlebook

  • Look: a Canvas theme that follows the system's light and dark setting and uses system fonts, a matching caption bar, and crisp high-density icons.
  • Files and sharing: Android's own picker for Open, Save and Export; Share and "Export to…"; recent files and launcher shortcuts.
  • Clipboard and printing: images on the clipboard both ways, drag-and-drop from Files, and Android's print dialog.
  • Trackpad: pinch to zoom, two-finger pan and rotate.
  • Speed and safety: a fast start with caches ready, autosave when Android closes the app, and a Meta + / shortcut helper.
  • Second accounts: full relocation, so other accounts on the same Googlebook can use Canvas too.
3

Many windows, better pen

  • GIMP's dialogs and multi-window mode as real Googlebook windows, each with its own taskbar entry and snapping.
  • Lower pen latency, barrel-button mapping, and a pen settings page.
  • SIMD speed-ups for arm64, and GPU presentation.
4

Follow upstream

  • Rebase onto GIMP 3.4 when it ships, for its new project format and native file choosers.
  • When GIMP moves to GTK4, switch to GTK4's own Android backend: real Android windows, the system file picker and IME, and no X server.

Four questions before I start

1 · The name

"Canvas" is already taken in a few places close to this app:

  • A live US trademark, CANVAS, covers graphic-design software (Canvas GFX, class 9).
  • Google's own Chrome Canvas is a drawing app on Chromebooks.
  • Instructure's Canvas is an education app with over 10 million Android installs.
  • Play already has drawing apps literally called "Canvas".
aKeep "Canvas". It's a free hobby app on GitHub, and you accept the overlap.
b"CanvasBook": part of your Book family and clearly not Chrome Canvas.
cI find three clean names and check each one.

2 · Repo visibility

recPublic from the first push. Free, unmetered 4-core CI runners. Git never holds keys.
altPrivate for now. That means 2-core runners and 2,000–3,000 CI minutes a month, which a few cold builds would use up.

3 · File access in the raw port

rec"All files access", switched on once in Settings. GIMP's own Open and Export dialogs then see Pictures, Downloads and Documents directly. It can be dropped once Android's picker arrives in Phase 2.
altNo broad access. Canvas only sees files opened with it and its own folder until Phase 2.

4 · How far to go before checking in

recPhase 0 then Phase 1, through to a v0.1 release. I'd check in only for decisions and for tests that need your hands, like the pen, pickers and printing.
altPhase 0 first, then a check-in with the first window on screen.
